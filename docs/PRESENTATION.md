### Slide 3: ตัวชี้วัดประสิทธิภาพและสูตรการคำนวณ
* **คุณลักษณะของ Process:**
  * `PID`: ตัวระบุ Process (P1, P2, ...)
  * `Arrival Time (AT)`: เวลาที่งานมาถึงระบบ
  * `Burst Time (BT)`: เวลาที่ต้องใช้ CPU ทำงานจนเสร็จ
  * `Priority`: ลำดับความสำคัญ (ตัวเลขน้อย = ความสำคัญสูง)
* **สูตรการคำนวณหลัก:**
  $$\text{Turnaround Time (TAT)} = \text{Completion Time (CT)} - \text{Arrival Time (AT)}$$
  $$\text{Waiting Time (WT)} = \text{Turnaround Time (TAT)} - \text{Burst Time (BT)}$$
  $$\text{Average Waiting Time (Avg WT)} = \frac{\sum \text{WT}}{N}$$

> **🎙️ บทพูดนำเสนอ (Speaker Note):**  
> *"ตัวชี้วัดที่เราใช้มี 2 ตัวหลัก คือ Turnaround Time ซึ่งคือเวลาตั้งแต่เข้ามาจนทำงานเสร็จ และ Waiting Time ซึ่งคือเวลาที่ต้องเสียไปกับการรอคอยในคิว โดยค่า Average Waiting Time ถือเป็นตัวชี้วัดหลักที่ชี้ขาดว่าอัลกอริทึมนั้นมีประสิทธิภาพสูงเพียงใดครับ"*

### Slide 4: 4 Scheduling Algorithms ที่ทำการจำลอง
1. **FCFS (First Come First Served):**
   * มาก่อนได้ก่อน (FIFO) เรียบง่าย แต่เสี่ยงต่องานยาวขวางทางงานสั้น
2. **SJF (Shortest Job First - Non-Preemptive):**
   * เลือกงานที่ Burst Time สั้นที่สุดในกลุ่มที่มาถึงแล้วมาทำก่อน (ให้ Avg WT ต่ำสุดตามทฤษฎี)
3. **Priority Scheduling (Non-Preemptive):**
   * เลือกงานที่มีความสำคัญสูงสุดก่อน (ตัวเลขน้อยสุด)
4. **Round Robin (RR):**
   * แบ่งเวลาเท่าๆ กันตาม **Time Quantum (Q)** เหมาะสำหรับระบบ Interactive / Time-Sharing

> **🎙️ บทพูดนำเสนอ (Speaker Note):**  
> *"เราได้จำลอง 4 อัลกอริทึมหลักครอบคลุมทั้ง FCFS แบบพื้นฐาน, SJF ที่เน้นลดเวลารอ, Priority ที่เน้นความสำคัญของงาน และ Round Robin ที่เน้นความยุติธรรมและการตอบสนองต่อผู้ใช้ครับ"*

### Slide 6: ผลการทดลองที่ 1 - Sample Case (Baseline Testing)
* **ชุดข้อมูล:** P1 (BT=5, AT=0), P2 (BT=3, AT=1), P3 (BT=8, AT=2)

| Algorithm | ลำดับการประมวลผล (Gantt Order) | Avg WT | Avg TAT |
| :--- | :--- | :---: | :---: |
| **FCFS** | P1(0-5) $\rightarrow$ P2(5-8) $\rightarrow$ P3(8-16) | **3.33** | **8.67** |
| **SJF** | P1(0-5) $\rightarrow$ P2(5-8) $\rightarrow$ P3(8-16) | **3.33** | **8.67** |
| **Priority** | P1(0-5) $\rightarrow$ P2(5-8) $\rightarrow$ P3(8-16) | **3.33** | **8.67** |
| **Round Robin (Q=2)** | P1(0-2) $\rightarrow$ P2(2-4) $\rightarrow$ P3(4-6) $\rightarrow$ P1(6-8) ... | 6.00 | 11.33 |

* **ข้อสังเกต:** ในเคสนี้ FCFS, SJF และ Priority ได้ผลเท่ากัน เพราะเมื่อ P1 ทำงานจบ ทั้ง P2 และ P3 มาถึงแล้ว และ P2 ดันมีทั้งเวลาสั้นกว่าและ Priority สูงกว่าพอดี

> **🎙️ บทพูดนำเสนอ (Speaker Note):**  
> *"ในเคสแรกตามโจทย์เอกสารหน้า 3 จะเห็นว่า FCFS, SJF และ Priority ได้ลำดับการรันเดียวกันคือ P1, P2, P3 ส่งผลให้ได้ Avg Waiting Time เท่ากันที่ 3.33 ในขณะที่ Round Robin มีการสลับ Context หลายรอบทำให้เวลารอคอยเฉลี่ยสูงกว่า"*

### Slide 7: ผลการทดลองที่ 2 - Complex Case (SJF Optimization)
* **ชุดข้อมูล 5 Process:** P1(BT=4), P2(BT=2), P3(BT=5), P4(BT=1), P5(BT=3)

| Algorithm | Avg Waiting Time | Avg Turnaround Time |
| :--- | :---: | :---: |
| **SJF (Non-Preemptive)** | **2.80 (ต่ำสุด)** | **5.80** |
| **Priority Scheduling** | 3.40 | 6.40 |
| **FCFS** | 4.20 | 7.20 |
| **Round Robin (Q=2)** | 4.60 | 7.60 |

* **จุดเน้น:** SJF ลัดคิวให้ **P4 (BT=1)** และ **P2 (BT=2)** ขึ้นมาทำก่อน ทำให้งานสั้นทยอยออกจากระบบได้อย่างรวดเร็ว ส่งผลให้ผลรวมเวลารอคอยเฉลี่ยต่ำที่สุดตามทฤษฎี

> **🎙️ บทพูดนำเสนอ (Speaker Note):**  
> *"สไลด์นี้คือหลักฐานยืนยันความสามารถของ SJF ครับ เมื่อจำนวน Process เพิ่มขึ้น SJF สามารถลดเวลารอคอยเฉลี่ยเหลือเพียง 2.80 ชนะ FCFS ที่ได้ 4.20 อย่างเห็นได้ชัด เพราะมันเลือกงานสั้นอย่าง P4 และ P2 มาทำก่อนทันทีที่ P1 จบ"*

### Slide 8: ผลการทดลองที่ 3 - Convoy Effect Demonstration
* **สถานการณ์จำลอง:** มีงานใหญ่มาก P1 (Burst = **24**) มาถึงก่อน P2 (Burst = 3) และ P3 (Burst = 3)

| Algorithm | Avg Waiting Time | พฤติกรรมที่สังเกตได้ |
| :--- | :---: | :--- |
| **FCFS** | **16.00** | P2 และ P3 ต้องติดหล่มรอ P1 ทำงานจนครบ 24 วินาที (**Convoy Effect**) |
| **Round Robin (Q=4)** | **4.67** | P1 ทำได้แค่ 4 วินาทีก็ถูกสลับออก ทำให้ P2 และ P3 ทำงานเสร็จอย่างรวดเร็ว |

* **สรุป:** Round Robin สามารถลดเวลารอคอยเฉลี่ยลงได้มากกว่า **3.4 เท่า** ในเคสที่มีงานยาวเข้ามาขัดขวาง

> **🎙️ บทพูดนำเสนอ (Speaker Note):**  
> *"นี่คือไฮไลท์สำคัญครับ เราทดสอบปรากฏการณ์ Convoy Effect ซึ่งเป็นจุดอ่อนคลาสสิกของ FCFS ผลปรากฏว่า FCFS ทำให้เวลารอคอยพุ่งไปถึง 16.00 หน่วยเวลา แต่พอใช้ Round Robin ตัวคิวหมุนเวียนช่วยให้ P2 และ P3 แทรกมาทำงานจนเสร็จได้ ส่งผลให้เวลารอลดฮวบเหลือเพียง 4.67 เท่านั้นครับ"*

### Slide 9: ตารางเปรียบเทียบจุดเด่นและข้อจำกัด (Trade-offs Matrix)

| Algorithm | ข้อดีเด่น | ข้อจำกัด | เหมาะกับงานแบบใด |
| :---: | :--- | :--- | :--- |
| **FCFS** | เข้าใจง่าย ไม่มี Overhead | เกิด Convoy Effect ได้ง่าย | งาน Batch Processing ทั่วไป |
| **SJF** | **Avg WT ต่ำที่สุด (Optimal)** | ทราบเวลายากในระบบจริง, งานยาวอาจ Starve | งานที่รู้เวลาประมวลผลล่วงหน้า |
| **Priority** | จัดการงานเร่งด่วนได้ดีเยี่ยม | งานความสำคัญต่ำอาจอดตาย (Starvation) | ระบบ Real-Time หรือภารกิจวิกฤต |
| **Round Robin** | **ยุติธรรม ตอบสนองผู้ใช้ได้เร็ว** | มี Context Switching Overhead | ระบบ Interactive / Desktop OS |

> **🎙️ บทพูดนำเสนอ (Speaker Note):**  
> *"เมื่อสรุปภาพรวม จะเห็นได้ว่าไม่มีอัลกอริทึมใดดีที่สุดในทุกสถานการณ์ แต่ละตัวมี Trade-off เฉพาะตัว เช่น SJF ดีเลิศเรื่องเวลารอแต่ต้องรู้เวลาล่วงหน้า ส่วน Round Robin ยุติธรรมและตอบสนองเร็วแต่มีต้นทุนในการสลับงาน"*

   * **คำตอบ:** แก้ไขด้วยเทคนิค **Aging** ครับ โดยเมื่อ Process รออยู่ในคิวนานขึ้นเรื่อยๆ ระบบจะค่อยๆ ปรับเพิ่มค่า Priority ของมันขึ้นทีละระดับ จนในที่สุดมันจะมีความสำคัญสูงพอที่จะได้รันครับ
2. **คำถาม: ทำไมไม่กำหนด Time Quantum ใน Round Robin ให้เล็กมากๆ เช่น 0.001 ไปเลยล่ะ?**  
   * **คำตอบ:** เพราะในระบบจริง การสลับ Process มีต้นทุนที่เรียกว่า **Context Switch Overhead** (การบันทึก Register และสลับ PCB) ถ้า Quantum เล็กเกินไป CPU จะเสียเวลาส่วนใหญ่ไปกับการสลับงานมากกว่าการทำงานจริงครับ
3. **คำถาม: ใน SJF ถ้า Process เข้ามาพร้อมกันแล้ว Burst Time เท่ากัน ระบบตัดสินใจอย่างไร?**  
   * **คำตอบ:** ในโปรแกรมของเรา หาก Burst Time เท่ากัน เราจะใช้ **Arrival Time (และ PID)** เป็นตัวตัดสินลำดับถัดไป (Tie-breaker) ครับ
